# Benchmarks

Raw results go to `bench/results/` and figures to `bench/plots/`; both are git-ignored and
regenerated by the commands below. Time only optimised builds:

```bash
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release && cmake --build build/release -j
```

## E9: what the DGA classifier costs (figure F12)

| Command | Measures | Writes |
|---|---|---|
| `build/release/dga_latency` | per name, in C++: the Public Suffix List split, the features, the trees, a first-seen name through `DgaCheck` (scored), and a name seen before (verdict cache) | `bench/results/e9/dga_latency.{csv,json}` |
| `bench/scripts/e9_end_to_end.py build/release/dnsentinel` | queries per second through the real daemon (dnsperf, offline, in a network namespace) with ML off, on with the verdict cache, and on scoring every query | `bench/results/e9/end_to_end.{csv,json}` |
| `python3 bench/scripts/plot_e9.py` | figure F12 from both | `bench/plots/F12_dga_overhead.png` |

`dga_latency` times the 551 names in `tests/unit/ml/dga_parity.tsv` by default (one per
registrable domain); `--names ml/data/dga_dataset.csv --limit 20000` times a larger sample.
The end-to-end script needs `dnsperf` (`sudo apt install dnsperf`) and user namespaces, as the
offline end-to-end test does.

Measured 2026-10-20 on an i5-13500H laptop under WSL2 (about 3 GHz there):

| | Median | p90 | p99 |
|---|---|---|---|
| First-seen name, scored | 40.8 µs | 54.0 µs | 63.2 µs |
| Name seen before, verdict cache | 0.34 µs | 0.53 µs | 1.07 µs |

E9's target, at most 50 µs median per first-seen domain, is met. End to end (best of five
runs, the daemon saturated by dnsperf): 43,259 queries/s with ML off, 41,692 (−3.6%) with the
verdict cache, 10,889 (−74.8%) scoring every query. The second is E9's "< 1% with a warm
verdict cache" target, not met: what remains is per-query bookkeeping (the name's string,
an event for each flagged query), inflated here by a query mix that is 27% DGA names.

On a laptop a run now and then lands on a slower core and loses ~25%, whatever the setup:
the setups are interleaved, and the summary reports each one's best run beside the mean.
